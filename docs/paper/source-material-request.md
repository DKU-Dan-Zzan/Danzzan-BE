# 논문 최종화를 위한 추가 자료 요청 목록

이 문서는 `danzzan-high-concurrency-ticketing-capstone-paper.md` 초안을 최종 제출본으로 다듬기 위해 필요한 자료를 정리한다.

## 1. 반드시 있으면 좋은 자료

| 자료 | 요청 내용 | 반영 위치 |
|---|---|---|
| 서비스 개요 | 프로젝트명, 개발 기간, 팀 구성, 각자 역할, 실제 축제 운영 여부 | 서론, 시스템 개요 |
| 화면 캡처 | 홈, 티켓팅 목록, 대기열, 예매 완료, 내 티켓, 관리자 티켓 관리 화면 | 시스템 설계, 구현 |
| 부하 테스트 원본 | k6 summary, Grafana 캡처, 서버 모니터링 캡처 | 성능 및 정합성 평가 |
| ERD 이미지 | 현재 DB 기준 전체 ERD 또는 티켓팅 중심 ERD | 데이터 모델 |
| 배포 구성 | 실제 운영 배포 구조를 민감 정보 없이 요약한 자료 | 전체 아키텍처 |

## 2. 있으면 논문 설득력이 커지는 자료

| 자료 | 활용 방식 |
|---|---|
| 실제 사용자 수 또는 접속 지표 | 실사용 검증 또는 운영 결과로 제시 |
| GA4 페이지뷰/이벤트 수 | 서비스 사용량 정량 근거 |
| 운영자 피드백 | 관리자 기능과 현장 운영성 평가 |
| 사용자 피드백 | 모바일 UX 개선 효과 설명 |
| 장애/이슈 대응 기록 | 한계 및 개선 방향을 더 현실적으로 작성 |

## 3. 민감 정보 제거 기준

논문, 발표자료, 제출용 이미지에는 아래 정보를 포함하지 않는다.

- 서버 IP, SSH 계정, pem 파일명 또는 키 내용
- DB host, DB 계정, DB 비밀번호
- JWT secret, API token, GitHub token, Jira token
- 실제 사용자 이름, 학번, 전화번호, 이메일
- 관리자 계정 또는 테스트 계정 비밀번호
- 내부망 Kafka 주소, RDS 원본 주소

필요한 경우에는 다음처럼 익명화한다.

| 원자료 유형 | 논문 표기 |
|---|---|
| 실제 서버 IP | `NHN Cloud VM` |
| 실제 DB 주소 | `MySQL RDS` |
| 실제 사용자 ID | `TEST0001 ~ TEST8000` 또는 `익명 사용자` |
| 내부 Kafka 주소 | `내부망 Kafka cluster` |
