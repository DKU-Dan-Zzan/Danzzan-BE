# Azure AI 추천 진단 (2026-10-14)

## 증상과 확인 결과

관리자 테마 화면에서 색상 추천과 두 배경 추천이 HTTP 504로 실패했다. 백엔드 OpenAI 요청 제한은 45초, 브라우저는 60초, Nginx는 75초였다. 같은 VM의 별도 Java 요청은 성공했지만, 실행 중인 애플리케이션의 실패 원인을 설명할 로그가 없었다.

두 OpenAI 클라이언트에 진단 로그를 추가하고 백엔드만 재배포한 뒤 실제 관리자 화면에서 확인했다.

| 요청 | 결과 | 백엔드 OpenAI 처리 시간 |
| --- | --- | --- |
| 테마 최초 추천 | HTTP 200 / HTTP_2 | 8.544초 |
| ticket 배경 추천 | HTTP 200 / HTTP_2 | 4.123초 |
| closed 배경 추천 | HTTP 200 / HTTP_2 | 3.938초 |
| 같은 프로세스에서 테마 재추천 | HTTP 200 / HTTP_2 | 6.615초 |

첫 세 요청은 화면에서 동시에 실행됐다. 두 번째 추천에서는 성공한 배경을 프론트 캐시에서 재사용했다. 화면에 유효한 원본형 시안이 표시됐으며, 다른 후보는 기존 색상 검증 규칙에 따라 제외됐다. 진단 작업에서 저장·전체 적용은 실행하지 않았다.

**재배포/프로세스 재시작 후 정상 동작은 확인했지만, 이전 타임아웃의 근본 원인은 확정하지 못했다.** 이번 변경은 관측 기능 추가이며, 타임아웃이나 전송 프로토콜을 바꾸지 않았다. HTTP/2 자체, 요청 크기, 동시 요청을 원인으로 단정하거나 영구 해결됐다고 해석하면 안 된다.

## 로그 범위

`OpenAiThemeRecommendationClient`, `OpenAiPosterFocusClient`가 다음 항목만 기록한다.

- 호출별 임의 UUID, 작업 종류, 검증된 배경 target
- 이미지 바이트 수, 모델/엔드포인트 설정 여부
- HTTP 상태, 협상된 프로토콜, 경과 시간
- 성공/오류 코드, 전송 실패의 예외 클래스명

API 키, 인증 헤더, URL/SAS, 프롬프트, 포스터 Base64, 업스트림 응답 본문 및 예외 메시지/스택은 이 진단 로그에 기록하지 않는다. 설정 여부는 값이 존재한다는 뜻이며 올바른 모델·엔드포인트라는 검증은 아니다.

VM에서 안전한 진단 항목만 조회하려면:

```sh
sudo docker logs --since 10m danzzan-azure-app-1 2>&1 | grep 'AI recommendation'
```

`start` 이후 `response` 없이 `OPENAI_TIMEOUT`이면 OpenAI HTTP 호출 중 시간 초과다. `response`의 상태가 429이면 요청 제한, 다른 비정상 상태면 업스트림 오류를 구분한다. `SUCCESS`는 클라이언트 응답 파싱 성공이며 이후 팔레트 검증이나 이미지 렌더링까지 보장하지 않는다. 로그 공유 시 전체 컨테이너 로그 대신 이 항목만 사용한다.

## 배포·보존·검증

- 수정한 두 운영 클라이언트 파일만 VM에 전달하고 `app` 이미지를 빌드·교체했다. Nginx는 백엔드 주소 갱신을 위해 설정 검사 후 reload했다.
- MySQL·Redis·Kafka 컨테이너 ID가 유지됐고, 새 배포 직전과 실제 화면 검증 후의 콘텐츠·이미지 참조·설정·테마 20개 테이블 해시가 일치했다. Blob 쓰기·삭제나 DB 변경은 수행하지 않았다.
- 최초 보호 검사에서는 준비 이후 별도로 실행된 홈 이미지 추가·순서 변경 요청 때문에 해시가 달랐다. 백엔드 이미지만 자동 롤백했으며 DB를 되돌리지 않았다. 최신 저장 상태를 기준으로 재배포한 이후 비교는 일치했다.
- 비밀값 노출 방지 회귀 테스트를 포함해 `ThemeRecommendationTest` 23건, `OpenAiPosterFocusClientTest` 4건이 통과했다. Docker 빌드, app health, 공개 HTTPS `/api/health`, `git diff --check`도 통과했다.
- 복구 경로: `/opt/danzzan/deployment-backups/20261014-ai-diagnostics`. 이전 소스는 `sources-before.tar.gz`, 이전 이미지 태그는 `danzzan-be:rollback-20261014-ai-diagnostics`다. 스키마 변경이 없으므로 애플리케이션 롤백에 DB 복원은 필요 없다.

재발하면 먼저 발생 시각과 위 로그의 호출 UUID/시간/상태를 확인한다. 원인 증거 없이 타임아웃 연장이나 자동 유료 재시도를 추가하지 않는다.
